## 0. 执行摘要(1 段话)

AegIsLoop Adaptive 面向 80% 年安全预算 < 50 万、专职安全 < 3 人的中小单位,以 **"8 个岗位化 Agent + 1 个灵活的人机协同层 = 1 支自适应增强的安全运营团队"** 为核心叙事,基于 **AgentTeams (Hiclaw) + Skill + MCP + RAG + 可观测** 五层架构(加 L0.5 人机协同层),沉淀 8 个岗位化 Agent(Leader / 资产 / 告警 / 漏洞 / 合规 / 响应 / **质量治理** / 复盘)+ **26** 个可复用 Skill + **5 套 RAG 知识库**(法规 / 漏洞 / Runbook / 复盘 / **供应链安全**)+ **6 类 MCP 工具**(资产 / SBOM / 告警 / 扫描 / 工单 / **通知通道**);严格按 L0-L3 四级安全分级封装,**A6 QualitySteward 实时质量治理**(输出质量监控 / Skill 偏差检测 / 规则漂移监控 / RAG 健康 / 证据完整性 / 自适应反馈)让系统真正 "Adaptive";人机协同层支持双模式(有 Web 平台的多角色协同,无平台的通过钉钉/企微推送对应角色);初赛 Demo 完全基于 Mock 数据,Apache 2.0 全栈开源。

## 1. 痛点与定位(场景价值 25%)

### 1.1 三重痛点

| 痛点维度 | 现状数据 | 业务影响 |
|---|---|---|
| **人力** | 80% 中小单位专职安全 < 3 人,大型金融/证券单位需 40-50 人 SOC 团队 | 招不到 / 留不住 / 7×24 排班难 |
| **预算** | 中小单位年安全预算 < 50 万,雇 50 人 SOC 团队年成本 > 2000 万 | 工具堆叠却无统一调度 |
| **合规** | 等保 2.0 + 网络安全法 + 数据安全法 + 个保法 + 生成式 AI 服务管理办法 多重叠加;2025 年监管月均通报增长 130% | 告警误报率 > 95%,人工响应 > 4h,远低于监管要求 30 分钟 |

### 1.2 现有方案的不足

| 方案 | 短板 |
|---|---|
| **传统 SIEM** | 告警洪水,误报 > 95%,无角色化协同 |
| **OpsPilot Zero**(官方示例) | 7 个 Agent 聚焦"故障响应",不覆盖"安全运营"全场景 |
| **通报整改白皮书**(他队作品) | 8 个 Agent 是"流程节点"非"岗位",无 Skill 抽象,无 MCP/RAG 体系 |

### 1.3 我们的差异化

| 维度 | 我们的做法 |
|---|---|
| **Agent 角色** | 团队岗位化 1:1 映射真实 SOC 8 大岗(Team Leader / CMDB 维护员 / Tier1 分析师 / IR / 内审员等) |
| **Skill 抽象** | 26 个 Skill 严格按附录 B 模板;L0-L3 分级 + 失败处理 + 复用度 |
| **A6 引擎** | A6 QualitySteward 让系统真正"Adaptive"——**没有 A6,AegIsLoop Adaptive 不会 Adaptive** |
| **人机协同层** | 双模式(Web 平台 / IM 通道)+ 角色化路由,不绑定具体人 |
| **编排流** | 3 类全调动 6-7 个 Agent(流 3 调动 7 个,管理路+技术路双路并发) |
| **安全边界** | 4 级分级 + H1/H2 审批关口 + "不可自动化清单"(8 条红线) |
| **可观测** | 16 核心指标 + 10 区团队大屏 + 链式 Hash 留痕防篡改 |
| **可复现性** | Apache 2.0 全栈开源,200-220 个工程文件,Mock 模式 36 小时可跑通端到端 |

### 2.5 L0.5 人机协同层(双模式)

**核心原则:不绑定具体人,只绑定角色(role)。**

| 模式 | 适用单位 | 实现 | 优势 |
|---|---|---|---|
| **模式 A:Web 平台**(AegisConsole) | 有自研/采购安全管理平台的单位 | 多角色登录,平台主动给 AI 提需求、审批、反馈 | 可视化强、可追溯、权限清晰 |
| **模式 B:IM 通道** | 无平台 / 移动办公 / 中小单位 | 钉钉 / 企微 / 飞书 推送审批卡,人通过 IM 反馈 | 0 部署成本、随时随地、降低使用门槛 |

**关键不变量**:无论有平台还是无平台,**审批/反馈协议完全一致**,只是"前端"换了。

**支持角色清单**:安全工程师 / 合规官 / DPO / 资产管理员 / 业务负责人 / 法务 / HR / 管理层

## 3. 3 类编排流(多 Agent 协同 25%)

### 3.1 编排流 1:告警触发流(Alert-Driven)

- **触发**:SIEM/EDR/WAF 推送 P2+ 告警
- **链路**:`SIEM → A0 Leader 创建事件 → A2 归并+分级+FP → A1 资产关联 → A3 沙箱 PoC → A4 合规 → A5 响应方案 → A6 QualitySteward 质量门禁 ① → H1+H2 合并审批 → A5 WAF 下发(L1) → A5 通知开发 → A3 复测 → A6 证据固化 → A0 Leader 关闭 → A7 沉淀 Runbook`
- **总步数**:**22 步**
- **调动 Agent**:**6 个**(A0 Leader + A1 + A2 + A3 + A5 + A6 QualitySteward)
- **关键 L 级**:A3 沙箱 PoC 为 L1,A5 WAF 下发为 L1,H1+H2 审批为 L2,A6 质量门禁为 L0
- **耗时**:30 分钟闭环(对比人工 4h)
- **详细 22 步**见子文档 `02-orchestration.md` §2.1

### 3.2 编排流 2:监管通报流(Regulator-Notice-Driven)

- **触发**:网信办 / 工信部 / 公安网监 通报
- **链路**:`通报接入 → A0 Leader 解析 → (A1 资产 || A4 合规 并发) → A6 QualitySteward 质量门禁 ① → H1 事实双签 → A3 验证 → A6 整改前证据固化 → A5 整改方案 → H2 三方会签 → A5 临时缓解(L1) → A5 永久修复 → A3 复测 → A6 生成回执 → A0 提交监管 → A7 异步复盘`
- **总步数**:**26 步**
- **调动 Agent**:**6 个**(A0 Leader + A1 + A3 + A4 + A5 + A6 QualitySteward)
- **特殊设计**:**H1 vs H2 严格分离**(告警场景可合并,监管场景不可合并)

### 3.3 编排流 3:新法规响应流(New-Regulation-Response)🆕

- **触发**:监管发布新法规(网信办 RSS + 法规库 diff 监控)/ 内部新业务上线
- **链路**:
  ```
  新法规事件
     ↓
  A0 Leader 接收 + 派工
     ↓
  A4 法规拆解 + 起草管理办法草案(管理路)
     ↓
  A0 Leader 派工 技术路:
     ├── A1 资产 / 影子IT 排查
     ├── A3 漏洞 / CVE 排查
     └── A5 响应预案调整
     (3 Agent 并发)
     ↓
  A4 汇总管理+技术 → 全单位合规落地报告
     ↓
  A6 QualitySteward 质量门禁 + 证据固化
     ↓
  A7 沉淀 Runbook(新法规落地模板)
     ↓
  管理层 H2 最终审批 + 落地跟踪
  ```
- **总步数**:**14 步**
- **调动 Agent**:**7 个**(A0 Leader + A1 + A3 + A4 + A5 + A6 QualitySteward + A7)
- **关键设计**:**管理路 + 技术路双线并发**;2 个 L2 审批关口(H1 合规官 / H2 管理层)
- **核心价值**:把"合规自评"从"被动检查"升级为"主动响应",应对监管高频变化

### 3.4 3 条编排流汇总对比

| 编排流 | 步数 | 调动 Agent | 关键 L 级 | 闭环时间 |
|---|---|---|---|---|
| **流 1:告警触发流** | 22 | 6 | L0-L2 | 30 分钟 |
| **流 2:监管通报流** | 26 | 6 | L0-L3 | 数日 |
| **流 3:新法规响应流** | 14 | **7** | L0-L2 | 1-2 周 |

**每条都调动 6+ Agent**,其中流 3 调动 7 个,符合多 Agent 协同"复杂度"评审要求。

### 3.5 4 级安全分级 + 双审批关口

| 等级 | 含义 | 触发条件 | 谁执行 | 留痕要求 |
|---|---|---|---|---|
| **L0** | 只读自动 | 查询 / 扫描 / 分析 | Agent | 留痕 |
| **L1** | 低风险自动 | 已知 IOC 封禁 / 普通账号冻结 / 非破坏性探测 | Agent | **强制留痕**(S19) |
| **L2** | 灰度+审批 | 单主机隔离 / 高权限账号封禁 / PoC 执行 | 对应角色审批 + Agent 执行 | 强制留痕 + 审批单 |
| **L3** | 仅规划必人工 | 关键业务隔离 / 全网封禁 / 数据回滚 / 对外报送 | **必须对应角色签字** | 强制留痕 + 双签 + 复盘 |

**双审批关口**:
- **H1 事实确认关**:确认漏洞/事件/违规事实成立
- **H2 执行审批关**:确认响应/整改/对外通知可执行
- 告警场景可合并,监管场景严格分离

### 3.6 不可自动化清单(8 条红线)

> 严守用户提供的"通报整改"白皮书的边界设计:

1. 严禁自动扫描未知资产(必须人工授权)
2. 严禁自动利用漏洞(必须双签 + 业务窗口)
3. 严禁自动修改生产数据(必须业务负责人签字)
4. 严禁未审核对外报送(必须法务审批)
5. 严禁删除/修改审计留痕(append-only 强制)
6. 严禁高敏告警(横向移动/数据外泄)自动关闭
7. 严禁跨境封禁/全网段封禁(必须双签)
8. 严禁未经脱敏对外发布复盘案例

## 附录 B:500 字项目简介(One-pager,严格 500 字)

> **字数控验**:中文标准计字法(汉字 + 英文单词 + 标点 = 1 字),**实测严格 500 字**。

AegIsLoop Adaptive(AegIsLoop 自适应 AI 安全运营)面向中小单位,核心理念是"8 个岗位化 Agent + 1 个灵活的人机协同层 = 1 支自适应增强的安全运营团队"。

**痛点**:80% 中小单位年安全预算 < 50 万、专职安全 < 3 人,雇不起 50 人 SOC;叠加等保 2.0、数据安全法、个保法、生成式 AI 合规,告警误报率超 95%,人工响应 4 小时,远不及监管 30 分钟。

**解决方案**:8 个岗位化 Agent 映射 SOC 八大岗——Leader、资产、告警、漏洞、合规、响应、质量治理、复盘。26 个 Skill 覆盖九大类,按四级安全分级(L0 只读、L1 自动、L2 灰度审批、L3 人工)封装。3 条核心编排流——告警流、监管通报流、新法规响应流(管理+技术双路),对齐比赛手册附录 A/B 模板。5 套 RAG + 6 类 MCP 工具,10 区大屏由 AgentScope Studio + AgentLoop 承载,人机协同层双模式——有 Web 平台的多角色协同,无平台则通过钉钉/企微推送反馈。

**差异化**:岗位化贴 SOC 协作;4 级分级 + 双审批关口严守"不可自动化清单";A6 QualitySteward 实时质量治理让系统"自适应";AgentTeams + Skill + MCP + RAG + 可观测五层架构可轻松复现。

**团队与开源**:3 人团队,10 年安全运营 + 2 年大模型经验;Apache 2.0 协议全栈开源,提供 Mock 剧本与部署文档;Roadmap:SIEM/SOAR 接入、多模态告警、跨团队协同、Adaptive Engine 自学新攻击手法。
