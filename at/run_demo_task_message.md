# AegIsLoop Adaptive — 事故任务消息模板

本文件包含 3 条事故任务消息。逐条复制到 Element Web 的 Team 房间,在输入框先 `@aegisloop-leader` 然后发送。**必须逐条发送**,等上一条报告完整输出后再发下一条。

## 任务 1: `alert_brute_force` (INC-2001)

**事故类型**:告警驱动
**scenario_id**:`alert_brute_force`
**事故 ID**:`INC-2001`
**风险分级**:L2(需 H1 + H2 审批)

```text
@aegisloop-leader

事故描述:web-app-prod-01(47.98.x.x,CentOS 7.9,生产)出现 SSH 暴力破解告警。SIEM 显示 5 个不同外部 IP 在 5 分钟内尝试 217 次 SSH 登录,失败率 100%,其中 1 个 IP 在威胁情报中标记为 Tor 出口节点。

初始告警:
- ALERT-2001 SSH 暴力破解(严重程度 CRITICAL,评分 92.5)
- 同时收到"SSH 22 端口被外网访问"的 Higress WAF 警告(规则 public-ssh-allowed 错误放行)

请基于以上初始告警,主动通过 HTTP mock 工具网关(<MOCK_TOOL_BASE_URL>)查询完整证据,完成:
1. 资产画像与 SBOM(从 a1 拉取)
2. 告警聚合 + IOC 富化(从 a2 拉取)
3. 漏洞可利用性验证(从 a3 拉取)
4. 应急响应计划 + 风险分级(从 a5 拉取)
5. A6 质量治理评估

最终输出事故报告,包含:影响资产、关键证据(日志/事件/IOC/CVE)、根因、修复计划(L1 自动 / L2 审批)、验证、A6 反馈。
```

## 任务 2: `regulator_notice` (INC-2002)

**事故类型**:监管通报驱动
**scenario_id**:`regulator_notice`
**事故 ID**:`INC-2002`
**风险分级**:L3(需 H1 + H2 + 业务负责人(角色)三审)

```text
@aegisloop-leader

事故描述:收到浙江省公安厅网络安全保卫总队邮件通报(编号 ZJWA-2026-0816-001,9:30 收到),要求 7 个工作日内(8-25 18:00 前)提交整改报告。

通报项:
- R-001(高):3 套生产数据库 admin 账户使用默认口令 admin/admin123,违反等保 2.0 三级 8.1.4.2
- R-002(严重):用户身份证号、手机号疑似通过海外 API(twelvedata.com)出境,违反数据安全法 第21条 / 个保法 第39条 / 数据出境安全评估办法
- R-003(高):3 个高敏感数据库未做个人信息保护影响评估(PIA),违反个保法 第55条

受通报资产:db-user-prod-01 / db-trade-prod-01 / db-mkt-prod-01(均为生产 PII-敏感数据库)。

请基于以上通报,主动通过 HTTP mock 工具网关(<MOCK_TOOL_BASE_URL>)查询完整证据,完成:
1. 资产画像确认(从 a1)
2. 漏洞/弱口令验证(从 a3)
3. 合规评估 + 法规匹配 + PIA 模板(从 a4)
4. 应急响应计划,按 24h/7d/30d 三阶段(从 a5)
5. 审批路由:H1 事实确认 / H2 执行审批 / L3 三审
6. A6 质量治理

最终输出事故报告,包含:通报项匹配、立即处置动作(L1)+ 短期整改(L2)+ 长期治理(L3)、审批清单、合规依据。
```

## 任务 3: `new_regulation` (INC-2003)

**事故类型**:新法规响应驱动
**scenario_id**:`new_regulation`
**事故 ID**:`INC-2003`
**风险分级**:L3(需三审 + 调动 7 个 Agent)

```text
@aegisloop-leader

事故描述:法务部告知《生成式 AI 服务管理暂行办法(2026 修订版)》将于 2026-09-01 实施,要求 3 周内(8-31 18:00 前)完成本公司 3 个生成式 AI 应用的合规对齐。

新法规关键条款:
- 第7条:深度合成服务算法备案
- 第10条:训练数据合规(不侵犯知识产权,涉及个信息需取得同意)
- 第14条:内容安全标识/过滤(涉政/涉暴/涉黄/涉谣言必须拦截)
- 第17条:用户实名认证+日志留存 6 个月
- 第22条:重大变更/新模型上线需重新做安全评估

涉及 AI 应用:
- ai-app-consult(AI 智能问诊助手,Qwen-72B-Chat,日活 28000,医疗 PII)
- ai-app-medreport(AI 病历摘要生成器,Qwen-72B-Chat,日活 8500,医疗 PII)
- ai-app-edu(AI 健康科普内容生成器,Qwen-14B-Chat,日活 120000)

请基于以上法规与受影响资产,生成管理路径 + 技术路径双路径整改方案:

管理路径(由 a4 合规主导):
- 草拟《生成式 AI 服务合规管理办法(试行)》
- 对 3 个 AI 应用做个人信息保护影响评估(PIA)
- 向网信办提交深度合成服务算法备案
- 更新用户协议,告知 AI 服务变更

技术路径(由 a5 响应主导):
- 对接阿里云内容安全 API(aliyun.green),覆盖 5 大类违规
- AI 输出统一加水印(数字水印+可追溯)
- 接入阿里云实名认证,3 个应用全量对接
- AI 请求/响应日志入 SLS 留存 6 个月(默认 90 天)
- 梳理 3 个应用的训练数据来源,补全数据授权链

调动 7 个业务 Agent 协作:
- a1 资产画像 / a3 漏洞与 SBOM / a4 合规 / a5 响应 / a6 质量治理 / a7 复盘 / a0-leader 调度

最终输出事故报告,包含:管理路径 4 项 + 技术路径 5 项 + A6 评估 + A7 知识回写条目。
```
