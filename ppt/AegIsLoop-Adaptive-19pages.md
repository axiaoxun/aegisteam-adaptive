## 第 9 页:第三章 · 多 Agent 协同设计(内容)

**评审维度**:多 Agent 协同(25%)

### 9.1 8 Agent 分工(对应 SOC 8 大岗)

| ID | 名称 | 岗位映射 | Skill 数 | 核心职责 |
|---|---|---|---|---|
| A0 | TeamLeader | SOC 主管 | 4 | 事故路由、审批路由、报告汇总 |
| A1 | AssetSteward | 资产管理员 | 4 | 资产画像、SBOM、影响面 |
| A2 | AlertSentinel | 告警分析师 | 4 | 告警聚合、IoC 富化、误报抑制 |
| A3 | VulnHunter | 漏洞工程师 | 4 | CVE/EPSS/KEV、漏洞-资产关联 |
| A4 | ComplianceGuard | 合规官 | 4 | 法规 RAG、PIA、备案 |
| A5 | ResponseCaptain | 应急响应 | 3 | 修复+验证+回滚、风险分级 |
| **A6** | **QualitySteward** | **质量治理(独家)** | **4** | **自适应反馈、漂移监控、健康度** |
| A7 | KnowledgeWeaver | 复盘 | 5 | 知识回写、复盘报告 |

### 9.2 任务拆解与上下文传递

- **A0 拆解**:根据事故类型(alert/regulator/regulation)下发 3 编排流
- **上下文传递**:每步通过 `evidence_id` 锚定证据,跨 Worker 共享 context_bus
- **状态流转**:`received → triaged → investigated → responded → verified → reported`

### 9.3 异常与冲突处理

- **跨 Agent 不一致**:A6 `cross_agent_consistency` 监控,> 3 处触发仲裁
- **Skill 调用失败**:A6 S26 `retry_with_backoff`,3 次失败升级 A0
- **审批冲突**:H1(事实确认)与 H2(执行审批)必须串联,不可并行

### 9.4 高风险动作安全边界

- **L0**:无审批(只读 / 通知)
- **L1**:安全工程师事后告知
- **L2**:H1 + H2 双签
- **L3**:H1 + H2 + 业务负责人三审 + 合规官 + DBA(法规通报场景)
- **L4**(极端):冻结 + 监管直报

### 9.5 协同示例:Flow 2 监管通报双路径

```
INC-2002 浙江网安通报
   ├─ A1 锁定 3 个 PII 数据库
   ├─ A3 验证 admin/admin123 + 2 起出境
   ├─ A4 PIA 评估 + 法规匹配 (R-001/R-002/R-003)
   ├─ A5 24h 阻断 + 7d PIA + 30d 管理办法
   ├─ A6 RAG 健康度重评(因新法规)
   └─ A0 报告 + 复盘
```
